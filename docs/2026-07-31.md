2. 内嵌汇编（Inline PTX）是啥？
🏠 形象比喻：“C++ 里的‘后门直通车’ / 汽车的手动挡强制提档”
C++ 是一种高级语言，正常情况下编译器（NVCC）会把你写的 C++ 代码翻译成 GPU 机器码。但有时候，NVIDIA 在 GPU 硬件里加了全新的黑科技功能（比如硬件级异步拷贝），而高级 C++ 语法里还没有对应的现成函数。
内嵌汇编（asm volatile(...)） 就是你在 C++ 代码里开后门，直接写 GPU 能听懂的底层“方言（PTX）”，跳过 C++ 编译器的语义检查，强制告诉 GPU 硬件执行某条具体的底层硬核指令。





Gpu和cpu的架构
在md上的7.31的图画的很好直接看那个
1.Gpu有很多核心，每个核心都有寄存器，往下是L1缓存，再往下是所有核心公用的L2缓存，然后通过数据总线连接gpu外的显存。思路是，越靠近计算核心存储量就越小，但计算核心能更快拿到放在那里的数据
Cpu核心少，每个核心都有寄存器，往下是L1缓存，再往下是L2缓存，到这里存储器都是计算核心各一个，往下的L3缓存所有核心共享，再通过数据总线连接外边的内存
2.数据传输效率方面，
gpu讲究不同层存储器之间路更宽更多，单位时间内传输数据量非常大，但路宽就要花时间排队保证数据不乱，且要等并排满了才发一次，所以针对单条数据，延迟会比cpu大得多【主要原因是 GPU 显存（DRAM/GDDR/HBM）在物理上离 GPU 核心较远，且为了追求极高吞吐，采用了更深的流水线和复杂的控制电路，而不是因为“等并排满了才发一次”】

--一个gpu有几十成百的sm处理器，一个处理器有几百个的ALU计算单元、一个L1缓存、一个寄存器和有特殊作用的其他功能单元，寄存器可以根据线程分配情况进行分割

--alu以32个为一组，设计上如果一个sm有更多的alu，则按32的倍数增加。因为warp有32个线程，32就可以把计算和数据存储传输对应上【目前最新的gpu，SM 划分为 4 个 Sub-core，每块 32 个 ALU和 1 个 Warp 调度器】

--如果有多个alu组，就可以同时算多个warp，或者把一个warp的无关联任务拆开让多个warp分别完成【Warp 是不可分割的硬件基本调度单位。一个 Warp（32 个线程）绑定在一起执行同一条指令（SIMT）。你说的“把无关联任务拆开”，在 GPU 里的硬件术语叫 ILP（Instruction-Level Parallelism，指令级并行）】

--一个sm的寄存器单元个数是固定的，寄存器会根据单个线程任务的复杂情况分配给每个线程，越复杂一个线程的寄存器存储单元就越多，存储空间就越大，warp数量越少，如果warp数量过少，就会导致alu组可能会空闲（warp算完了数据搬走新的数据搬进来需要时间），导致浪费【Occupancy Trade-off (占有率权衡)】






Cpu用各种办法尽可能地保证少量的数据得到最快的传输和处理，方法有：
--缓存做得大且多一级，可以预读取很多数据，保证更高的缓存命中率
--寄存器靠近cpu，不过gpu和cpu都一样
--分支预测，对于判断逻辑，被设计过的计算单元会提前猜，正确率很高，确定哪条路后直接用提前算好的，就相当于这段逻辑判断代码不花时间
--把指令拆分，同时执行这些指令，对于不需要前面数据的就很快了（如果需要前面的数据呢？）
--一个cpu核心（core）有非常多不同类型的计算单元，功能不同，可以很好地分工复杂代码
